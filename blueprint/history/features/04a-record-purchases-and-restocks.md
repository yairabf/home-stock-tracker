# Feature: Record purchases and restocks

**From build-plan:** feature 4a (part of feature 4)
**Status:** complete

## Goal

Add a focused service/API flow for recording purchase-oriented inventory events without requiring callers to construct raw inventory event payloads. The flow accepts a product, quantity/unit, event kind, and source, validates the product and request, and records an append-only `PURCHASED` or `RESTOCKED` event for later inventory estimation and grocery-list resolution.

## In scope

- Add a purchase/restock request DTO with product ID, event kind, optional non-negative quantity, optional unit, required trimmed source, optional metadata, and optional confidence.
- Expose `POST /api/v1/inventory/purchases` as the purchase-oriented endpoint.
- Accept only `PURCHASED` and `RESTOCKED` event types through this endpoint.
- Reuse the existing inventory event persistence and response shape.
- Validate that the referenced product exists before creating the event.
- Preserve the append-only event model and server-generated timestamp.
- Add unit coverage for valid purchase/restock recording and invalid product/event inputs.
- Add e2e coverage for successful requests and HTTP validation/not-found behavior.

## Out of scope

- Updating grocery-list item status or linking an event to a grocery item. That is feature 4b.
- Completing multiple or partial grocery-list items. That is feature 4c.
- Derived stock state, consumption statistics, or prediction logic.
- Household profile, authentication, MCP exposure, and Hermes conversation behavior.
- Client-provided timestamps or arbitrary inventory event types through this endpoint.

## Data / contracts

### `POST /api/v1/inventory/purchases`

Request:

```json
{
  "productId": "uuid",
  "eventType": "PURCHASED",
  "quantity": 2,
  "unit": "liter",
  "source": "hermes_whatsapp",
  "confidence": 1,
  "metadata": { "receiptReference": "optional" }
}
```

- `productId`: required UUID referring to an existing `Product`.
- `eventType`: required enum value, restricted to `PURCHASED` or `RESTOCKED`.
- `quantity`: optional non-negative number; `0` is valid when the caller explicitly records zero quantity.
- `unit`: optional string.
- `source`: required non-blank string, trimmed by transformation.
- `confidence`: optional number carried through as provided; range validation remains deferred to the broader event contract.
- `metadata`: optional JSON object.

Response: HTTP 201 with the existing `InventoryEventResponseDto` fields: `id`, `productId`, `eventType`, `quantity`, `unit`, `timestamp`, `source`, `confidence`, and `metadata`.

Errors:

- HTTP 400 for malformed input, invalid UUID, unsupported event type, missing source, or invalid field types.
- HTTP 404 when `productId` does not reference an existing product.

The event's `timestamp` is generated by Prisma. The endpoint does not accept a timestamp and does not mutate `GroceryListItem` rows.
